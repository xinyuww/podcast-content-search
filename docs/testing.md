# 测试与验收

更新：2026-10-03。自动化通过、真实 API 联调、浏览器实际播放和推荐效果是不同层面的证据，下文分别记录。

## 网页检查：适用于新克隆的仓库

需要 Node.js 24 和安装好的 npm 依赖，不需要 Python、原始素材缓存或真实模型调用。

```sh
npm run test:web
npm run typecheck
npm run lint
npm run build
npm run test:production
```

- `test:web` 覆盖播放器状态、需求结构校验、检索规则、音频格式与接口数据契约；Node 检索通过已提交的 fixture 与 Python 参考结果对照。
- `build` 先校验快照与发布边界，再构建 Next.js。
- `test:production` 必须在构建之后运行，启动真实生产服务并检查页面与 API，但模型响应使用测试替身。
- `npm test` 运行 Python 和网页测试，不包含生产构建与 HTTP 测试，也不是新克隆仓库的最小验证入口。

## Python 与素材检查

本地素材维护环境需 `.venv`、源数据库及相应缓存；部分流程还依赖 ffmpeg / ffprobe 和 `requirements-retrieval.txt`。具备这些条件后运行：

```sh
npm run test:python
npm run snapshot:verify
```

`test:python` 检查本地入库、字幕、分章、标注、检索与导出逻辑。快照校验不会重新下载、转录或生成向量。源库重建可能级联清除派生数据，不应为了启动网页运行重建流程。

## 真实 API 验收：显式运行，会产生调用

本地服务端配置 `OPENAI_API_KEY` 后，可运行：

```sh
npm run needs:evaluate
node scripts/verify-public-demo.mjs https://podcast-content-search.vercel.app
```

前者运行合成需求对话场景，后者检查公开页面和真实需求、检索接口。需要网络与模型额度；不要把它们误认为完全离线测试。音频维护另有 `node scripts/verify-hosted-audio.mjs`，需要本地原媒体比对云端分段字节。

## 人工演示检查

1. 首页输入需求，完成追问后自动生成拼盘；检查无匹配与部分匹配提示。
2. 打开 `/demo`，确认有声音且进度前进，测试暂停、拖动、倍速和切段。
3. 在片段边界确认自动换段；进入全集，再返回原拼盘位置。
4. 断网或加载失败后确认提示与重试；在手机和常用浏览器重复关键播放操作。

完整跨浏览器、手机实机验收、全部素材逐句核听和独立推荐质量评估仍未完成。当前项目以可演示产品原型为定位。
