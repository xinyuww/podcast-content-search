# 声签 MVP：产品架构与用户流程

## 1. 产品定义

声签不是按节目名搜索的播客目录，而是一个按“内容需求”工作的搜索和策展工具。第一版跳过多轮对话，用户提交一个自然语言问题后，系统直接检索带时间戳的播客片段，并将不同节目的观点组合成一份 15–25 分钟的声音拼盘。

第一版验证的核心假设是：相比得到整集列表，用户更愿意消费一条由多个高相关片段组成、能够形成完整思考路径的播放列表。

## 2. 用户流程

```text
首页
  ↓ 输入一个具体问题
“最近工作很迷茫，想听一些关于职业选择的讨论”
  ↓
检索中
  ├─ 查询向量化
  ├─ 全文 + 向量召回候选片段
  ├─ 相关性与内容质量重排
  └─ 去重、控制节目多样性、生成内容顺序
  ↓
声音拼盘
  ├─ 查看策展说明与总时长
  ├─ 从头播放或单独播放片段
  ├─ 阅读片段摘要与选择理由
  └─ 对感兴趣的内容打开完整单集
```

### MVP 页面状态

1. **问题输入**：默认展示一个真实使用场景，用户也可替换文字。
2. **匹配反馈**：展示候选集规模和正在生成拼盘的反馈。
3. **拼盘结果**：展示策展逻辑、五个片段、来源和播放器。
4. **完整单集入口**：Demo 中为提示；接入 RSS 后跳转原节目或平台页面。

## 4. 检索策略

第一版建议使用混合检索，而不是只依赖向量相似度。

```text
final_score =
  0.45 × vector_similarity
  + 0.25 × full_text_score
  + 0.15 × editorial_quality
  + 0.10 × popularity_score
  + 0.05 × recency_score
```

检索 30–50 个候选片段后进行二次重排，并应用以下约束：

- 同一单集最多保留一个片段；
- 同一节目最多占拼盘的 40%；
- 片段必须能脱离完整上下文理解；
- 优先组合“理解问题 → 不同观点/故事 → 可执行建议 → 收束”的内容路径；
- 默认总时长控制在 15–25 分钟。

## 5. 模拟数据库策略

当前界面使用 `app/mock-data.ts` 中的结构化样本，完整模拟数据库返回的数据对象和产品交互。样本中的节目名与文案仅用于产品演示，不代表已获得真实节目音频或转录授权。

接入真实数据时：

1. 通过 RSS 获取节目和单集元数据，不抓取平台网页；
2. 只处理自有、授权或开放许可音频；
3. 转录后按说话人、停顿和语义边界切成 2–6 分钟片段；
4. 将转录、摘要、主题和 embedding 写入 Supabase；
5. 完整单集入口指向内容方允许的原始地址。

## 6. MVP 与后续范围

### 当前第一版

- 单问题输入；
- 模拟搜索与生成反馈；
- 五段式内容拼盘；
- 单片段播放、进度和固定播放器；
- 节目、单集、嘉宾、原始时间点与选择理由；
- Supabase / pgvector 数据库结构草案。

### 第二阶段

- 真实 Supabase 查询；
- RSS 导入器与后台内容状态；
- Whisper 转录及语义切片；
- OpenAI embedding 与重排；
- 真实音频播放器及跳转；
- 搜索日志与结果反馈。

### 暂不实现

- 多轮对话式需求识别；
- 用户登录、收藏与跨设备历史；
- 自动抓取受版权保护的内容；
- 对外宣称未经验证的真实播放量。
