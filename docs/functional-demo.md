# 固定 Demo 与播放交互

更新：2026-10-03。固定试听页为 [/demo](https://podcast-content-search.vercel.app/demo)，用于直接体验真实章节播放，不调用需求模型或查询向量接口。首页则通过需求对话生成动态拼盘，见[动态拼盘](dynamic-playlists.md)。

## 演示流程

1. 打开固定 Demo，获得 4 段、共约 19 分 13 秒的真实节目原声。
2. 播放第一段或选择任意片段；支持暂停续播、进度拖动、前后 15 秒、倍速、上一段／下一段。
3. 到达章节结束时间自动播放下一段；最后一段结束后显示完成。
4. 展开字幕，点击时间点定位；也可打开节目原页面。
5. 选择从该章节起点听全集，或从全集开头听。返回拼盘时恢复进入全集前的位置，并保持暂停，点击播放继续。

固定 Demo 不根据输入选择内容，也不会在动态检索失败时偷偷替代推荐结果。返回首页会重新开始需求流程；当前没有账号、跨刷新会话保存或收听历史。

## 当前播放实现

`app/demo/page.tsx` 在服务端通过 `server/snapshot.ts` 读取 SQLite 中的固定拼盘。`GET /api/demo` 提供同一份数据。固定与动态拼盘共用播放器，均直接读取 Vercel Blob 托管的原单集 MP3 / M4A。

数据库保存音频 URL 和章节起止时间，不保存音频二进制。播放器以原单集的时间轴定位，界面显示片段内进度；浏览器通过媒体请求按需缓冲，无需等待完整单集下载。加载连续 20 秒无进展或总计超过 120 秒会显示重试入口，迟到的播放事件不会隐藏失败状态。

界面使用深夜电台风格：深色背景、灰白文字、黄绿色强调色与播放时旋转的黑胶。手机布局保留唱片并适配上下排列。品牌与主文案沿用「声签」「调到你的频率」「世界很吵。听点与你有关的。」

## 本地运行与更新固定选段

日常体验只需按 [README](../README.md#本地运行) 安装 Node 依赖并运行 `npm run dev`，打开 `/demo`。不需要 Python、源数据库或本地音频缓存。

仅在修改固定选段时，使用具备源素材、Python、ffmpeg / ffprobe 的本地维护环境：

```sh
npm run demo:prepare
npm run snapshot:export
npm run snapshot:verify
```

选段配置在 `data/demo-playlist-selection.json`。准备脚本生成 `data/demo-playlist.json` 和 `data/raw/legacy-demo-audio/` 中的离线试听产物；它们不作为线上静态媒体发布。快照导出会将旧路径替换为 Blob 原音频地址及对应偏移，网页最终读取 `server/data/corpus.sqlite3`。
