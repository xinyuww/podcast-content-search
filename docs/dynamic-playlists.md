# 从结构化需求到动态拼盘

2026-10-01：已接通本地检索、拼盘组装和原音频播放。使用现有 15 期素材、164 个可独立检索章节，无需重新标注或重做内容向量。

## 数据流

```mermaid
flowchart LR
    N[对话或恢复的结构化需求] --> P[POST /api/playlists]
    P --> S[本地 Python 检索服务]
    DB[(SQLite)] --> S
    S --> Q[查询向量与章节向量比较]
    Q --> R[最多 30 段：标签排序和排除]
    R --> C[选择 3–5 个完整章节，总长 10–30 分钟]
    C --> UI[现有播放器]
    A[15 期本地原音频] --> M[HTTP Range 媒体服务]
    M --> UI
```

`ready_to_recommend=true` 且没有待发送的修改时，页面提供「按这个需求生成拼盘」。请求只传 `search_query`、`preferences`、准备状态和词表版本，不传完整对话。用户也可以在「恢复已保存的需求」粘贴此前导出的 JSON；恢复时校验结构、词表与原话引用。

## 服务与启动

`npm run dev` 通过 `scripts/dev.mjs` 同时启动 Python 服务（固定监听 `127.0.0.1:8766`）和 vinext 页面；一个子进程退出时会停止另一个。需要已有 `.venv`、tiktoken 和 ffprobe。`npm start` 同样启动本地 Python 服务和生产构建的页面服务。不要同时运行多个实例占用 8766 端口。

开发环境的 Worker 无法直接连接宿主机 loopback，因此 `vite.config.ts` 将 `/api/playlists` 和 `/media/episodes/` 交给 Vite 的 Node 代理。构建后的本地 Node 服务通过 `server/corpus.ts` 的固定目标桥接到 Python；该模块也由 Worker 入口分流使用。这里依赖本机 SQLite 和文件系统，不是可直接上传到云端的服务布局。

```sh
# 正常使用：新查询需要 OpenAI 网络
npm run dev

# 检索只使用已有查询向量缓存，不向 OpenAI 请求新向量
PODCAST_OFFLINE=1 npm run dev

# 仅单独启动 Python 服务（通常不需要）
npm run corpus:serve
```

`PODCAST_OFFLINE` 只控制检索向量调用，不会把需求对话变为离线模型。当前按用户要求暂停 OpenAI 网络测试；浏览器联调用恢复的预设需求和真实缓存向量完成。

## 拼盘选择

复用 `search_content.py`：同模型查询向量 → 余弦相似度至少 0.35 → 最多召回 30 个章节 → 硬排除用户明确拒绝的内容 → 标签规则排序。

`playlist_service.py` 在这 30 个候选中枚举 3–5 段组合，约束如下：

- 总时长 600–1800 秒，保留完整章节边界，不裁短章节凑时长。
- 去除重复章节；同一期内的章节不能重叠。允许同一期中多个独立章节。
- 以平均检索分为主，小幅奖励不同节目 / 单集，偏好接近 20 分钟。
- 组合分 = 平均规则分 + 0.015 × 节目数 + 0.005 × 单集数 − 0.02 × 距 20 分钟的偏差 / 600。
- 保留检索排序作为播放顺序；尚未生成额外的叙事串联或串场语音。

找不到合规组合时返回 `insufficient_coverage`、`playlist=null` 和解释，不降低相似度阈值、不插入固定示例。选好后按最终章节重新计算未覆盖偏好；有缺项时返回 `partial_match`，页面展示具体缺项。这些权重和阈值是初版启发式规则，不是推荐质量保证。

## 原音频与播放器

媒体地址为 `/media/episodes/<episode-id>`。服务通过 SQLite 中已登记的 audio asset 找到文件，只允许 `data/raw/audio/` 内的文件；不能用 URL 读取任意磁盘路径。支持 GET、HEAD、单段 byte Range、后缀 Range、206 和 416。通过 ffprobe 识别真实容器，避免扩展名 `.mp3` 实际为 MP4/AAC 时返回错误 MIME。

动态片段的 `audioUrl` 和 `episodeAudioUrl` 使用同一份原音频。新增 `audioOffset=start`：播放器在加载后定位到原时间点，界面进度按片段相对时间显示，到章节终点停止当前音频并自动切换下一段。浏览器只需按 Range 读取相关数据，不重新下载素材或运行 ffmpeg 裁切。

固定示例仍使用裁好的 MP3，默认 audioOffset=0。进入全集时使用原始绝对时间；返回拼盘恢复片段相对位置。切换回对话会暂停播放并保留位置；生成新拼盘才替换并释放旧控制器。时间边界由浏览器媒体事件和计时器控制，存在浏览器调度精度限制，不等同于生成采样级裁切文件。

## 存储与边界

- 只读现有 SQLite，不新增或修改数据库表。
- 新的网页查询向量不写入磁盘，也不保存完整需求或拼盘；可读取已有的离线查询向量缓存。
- API key 仍仅由后端读取，不返回给浏览器。
- 查询最多 1000 字，每类偏好最多三个，请求体最多 16 KB，同时最多处理两个拼盘任务；未缓存查询单次模型请求超时 35 秒，不自动重试。
- 音频与标签仍有原有审核限制。当前没有明确情感支持标签，相关需求会显示未覆盖。
